Oryntra AI

Analysis Methodology

Effective August 3, 2026 · Version 0.9
Design boundary: Oryntra separates server-side market-data processing from public visualization. The public API is intended to return derived intelligence, while TradingView independently supplies the embedded chart.

1. Analysis pipeline

  1. An authenticated user submits a ticker and analysis lookback.
  2. The server checks account entitlement, market-data license mode, subscription status where enabled, and the daily ticker quota.
  3. The private provider adapter obtains candle data for server-side computation.
  4. The indicator and pattern engines calculate derived features.
  5. The setup scorer assembles directional evidence, conflicts, quality, and risk-planning levels.
  6. A strict public serializer removes raw and reconstructable market-data fields before the response leaves the server.
  7. The client asks TradingView's hosted widget to display the symbol independently.

2. Derived technical features

Depending on data availability, Oryntra may calculate SMA and EMA relationships, RSI, MACD, stochastic oscillator, Bollinger position, ATR and normalized volatility, ADX and directional movement, Williams %R, OBV interpretation, VWAP relationship, Ichimoku state, momentum, trend strength, relative participation, divergence, and support/resistance zones.

Numerical indicator values are mathematical derivatives of the server-side observations. They are not an official quote and can differ from another platform due to timeframe, adjusted data, session handling, rounding, and provider methodology.

3. Pattern detection and timing

Independent detectors evaluate candlestick formations, chart structures, trend continuation/reversal shapes, fair-value gaps, liquidity events, support/resistance interactions, and break-of-structure concepts. Pattern records can include the detector's label, bias, confidence, detected time, trigger context, and derived zone boundaries. A timestamp describes when the software identified evidence in the analyzed series; it is not a trade recommendation.

4. Setup and confidence scoring

Oryntra combines trend, momentum, volatility, participation, structure, pattern, and risk evidence. Conflicting evidence reduces conviction. Quality and confidence scores are ranking tools, not calibrated probabilities unless a specific validation report states otherwise. Scores do not guarantee profit or future accuracy.

5. Educational trade-planning levels

The engine may derive an entry zone, ideal reference entry, stop, target, direction, and risk/reward ratio from volatility, structure, and detected levels. These are hypothetical planning outputs. They are not current quotes, executable orders, or personalized position-sizing advice.

6. Public market-data boundary

The public serializer blocks direct fields and arrays such as open, high, low, close, raw volume, candles, bars, OHLCV, provider responses, downloadable history, timestamps series, previous close, daily change, and raw market-data metadata. Public routes expose only an allowlisted derived-analysis contract. Private research routes are disabled by default and must not be exposed on a public host.

This technical boundary does not itself create legal rights. Oryntra's operator must use a provider agreement that permits the intended commercial, derived-output, and end-user distribution model. The server defaults to owner-only personal research until an approved business license is deliberately enabled.

7. Validation and research separation

Pattern Lab, historical backtests, cache inspection, and developer routes are private research systems. Their output does not automatically alter production scoring. Candidate changes should be evaluated on holdout periods, multiple regimes, realistic costs, sample size, stability, and reproducibility before promotion.

8. Known limitations

  • Technical analysis is backward-looking and regime-dependent.
  • Pattern thresholds can generate false positives and false negatives.
  • Data corrections and corporate actions can change historical results.
  • Multiple derived features can be correlated.
  • AI explanations can be incomplete or wrong.
  • Embedded charts may use different data or settings from the server-side analysis.
